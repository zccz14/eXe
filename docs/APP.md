# macOS 桌面客户端（`clients/macos`）

一个 SwiftUI 外壳，**托管**设备进程。它不是第二个实现：协议、密码学、中继全都还是
`exe` 二进制干的活，App 只做四件事——托管进程、读写同一份配置、报状态、查权限。

```sh
scripts/build-app.sh          # → dist/exe.app
open dist/exe.app
```

## 为什么是 App 托管，而不是 launchd

macOS 的授权（屏幕录制、辅助功能、输入监控……）**按代码签名身份记账**。现在的 CLI 是
adhoc 签名，标识里带着构建哈希：

```
v0.6.2: Identifier=exe-4e4c2b2de15bcc75
v0.6.3: Identifier=exe-82202fde390d6191
```

对系统来说这是两个不同的程序，于是每次升级授权都作废、重新弹框、重新"退出并重新打开"。

把设备放进 `.app`（固定 `CFBundleIdentifier=io.ntnl.exe`），授权就挂在一个稳定的身份上：

- 权限窗口报告的就是**真正跑命令的那个进程**的权限（App 是它的宿主 / responsible process）
- 升级本身不再改变身份

代价：设备只在 App 运行时在线。个人 Mac 上这是对的（桌面自动化本来就要求用户的图形会话）；
服务器继续用 `exe` + launchd。两种模式可以随时切换：设备页有「停用系统服务」按钮，
把地址从 launchd 手里收回来交给 App。

> 仍然没有解决的一件事：**签名**。本机 adhoc 能跑，但要让授权跨版本存活、要分发给别人，
> 需要 Developer ID 证书 + 公证。这一步只影响分发，不影响架构——bundle id 已经固定好了。

## 四个页面

| 页面 | 做什么 |
|---|---|
| 设备 | 本机地址、谁在托管、启动/停止/重启、设备日志（同时落 `~/Library/Logs/eXe/app.log`） |
| 调用方 | `trust` 列表增删；写完后设备 2 秒内自己发现，不用重启 |
| 权限 | 屏幕录制 / 辅助功能 / 输入监控 / 自动化 / 完全磁盘访问：状态、去授权、**试一下** |
| MCP | 调用方地址、工具前缀、设备表编辑、harness 配置片段一键复制 |

「试一下」不是多余的按钮：`CGPreflightScreenCaptureAccess()` 说 true 而实际截图仍然失败，
是这几代系统上真实存在的情况。所以每项除了查询 API，还能真的做一次（截图、读前台焦点元素）。

## 它不做什么

- 不解析 TOML 之外的东西，不实现签名/密封/协议
- 不替你授权：macOS 的 TCC 不允许程序自我授权，任何号称能这么做的工具都值得怀疑
- 不碰中继：所有网络往来都是 `exe run` 自己签的
