# eXe · Soul

> eXe (Executable) 是 △○✕□ 里的 ✕：可变数的那一个。CTX 改名 Docs 之后，X 让给了执行面。

## 它是什么

一条**只关于「在这台设备上执行，并证明结果」的通道**。人在浏览器里批准一台设备，此后云端可以把调用投递过去，设备验证、执行、封好、回传。

## Statement List

1. **端侧是信任的根。** Cloud 发来的任何调用，在端侧一律先当作不可信输入，直到它通过了设备本地固定的公钥验证。不因为"它来自服务端"而放行。
2. **一次批准只钉一件事：这个账号的签名公钥。** 设备不信任云端的数据库、不信任队列、不信任 worker 的鉴权结果，只信自己磁盘上那把公钥。
3. **结果由设备封装，云端只是信封中转。** 落库的是密文；明文只在内存里存在一瞬间。数据库、备份、日志、队列都不该出现结果正文。
4. **云端不是安全边界。** 它可以路由、排队、限流、计费，但不能仅凭"我是服务端"获得执行权，也不能改变一次调用的内容。
5. **端侧默认收窄。** 未经本地策略显式允许的工具，签名合法也不执行。默认策略只允许无害工具，`bash` 之类的需要人自己打开。
6. **一次调用只有一份权威记录。** 签名覆盖调用内容、设备、账号、有效期与一次性的 nonce；重放、跨设备、跨账号、过期一律无效。
7. **eXe 只做执行面。** 它不是 Agent，不是模型网关，不是聊天界面。它不替你决定做什么，只负责"做了，并给你证据"。
8. **人可以随时切断。** 撤销即吊销设备令牌，立刻生效；并且撤销不会把已有密文变成明文。
9. **迁移是形态对齐，不是重写。** Cybion Worker 的 SSE 订阅 + 回传语义保留可对齐的形状；被废弃的是它的信任模型，不是它的调用形态。

## 它不应该变成什么

- 不是一个"服务端说跳就跳"的远程管理木马；任何默认信任云端的实现都是错的。
- 不是把结果明文塞进 D1 然后声称"我们内部很安全"。
- 不是多租户的共享执行池：一台设备只属于一个账号，除非人显式共享。
- 不是只有浏览器能用的东西：设备、CLI、移动端都应该是同一套协议的一等公民。
- 不是为了兼容 Cybion 而把旧的"令牌即权限"模型再带进来。

## 调用形态（不可破坏的骨架）

```
人批准设备 → 设备钉下账号公钥
   ↓
云端排队调用 → SSE 下发 {call, sig}
   ↓
设备: 验签 → 验有效期/nonce → 查本地策略 → 执行
   ↓
设备: X25519 封装结果 + Ed25519 签名 → POST 回传
   ↓
云端: 只存信封；读的时候才解开，读完不落明文
```
