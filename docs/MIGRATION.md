# 从 Cybion Worker 迁移到 eXe

## 保留什么

| Cybion Worker | eXe | 说明 |
|---|---|---|
| 登记 + 批准 | 设备的 `trust` 配置 | eXe 没有登记批准流程；信任由人在设备上写死 |
| `GET /worker/v1/.../events`（SSE） | `GET /v1/devices/{address}/stream` | `call` / `cancel` / `heartbeat` 事件同构 |
| `POST .../calls/{id}/received` | 同名 | 语义不变 |
| `POST .../calls/{id}/result` | 同名 | 载荷从明文 JSON 变成密封信封 |
| `x-cybion-worker-boot-id` | 无 | 重投与幂等取代了「重启即判失败」：未完成的调用会被重投，设备进程内按 `call_id` 去重 |

## 改变什么

1. **令牌不存在。** Cybion 里持有 Worker 令牌就能让设备执行；eXe 里每次请求都自签，
   执行必须由设备 `trust` 列表里的地址签发。
2. **结果不再明文落库。** 设备把正文封给调用方的 X25519 公钥（与签名密钥同一把），
   D1 只存信封；解密只发生在浏览器里。
3. **端侧只有信任列表。** 没有本地策略文件：签名来自 `trust` 里的地址就执行（shell 也是）。
   要收回权限，就把那个地址从 `trust` 里删掉并重启。
4. **地址就是身份。** 不再有 `device_id` 与两把公钥：设备地址是它的 Ed25519 公钥，
   调用方把地址记进自己的本机名单，设备用调用方地址建立信任。
   云端不保存任何人的设备名单，所以换浏览器就是重新填一次地址。

## 迁移步骤

1. 先让 eXe 独立跑通：控制台加地址、SSE 投递、结果解密、移除设备。此时 Cybion 完全不受影响。
2. Cybion 生成 Ed25519 密钥对，**私钥由 Cybion 托管**，只把公钥交给用户——地址就是这把
   公钥的 base58，设备侧只需要这一个字符串。用户手里没有私钥，也不需要理解私钥；
   签发与控制都在 Cybion 侧。（按用户还是按设备发地址，见下文第 3 条建议。）
3. 逐台设备装 eXe（`curl -fsSL https://exe.ntnl.io/install.sh | sh && exe`），把**那台设备对应的**地址写进 `trust`（`exe trust <地址>`，热生效，不用重启）；
   同一台机器上的 `cybion-worker` 随之停掉。
4. 观察一段时间后，Cybion 的 `/worker/v1/*` 路由、`worker_calls` 表与
   `cybion-worker` 发布流程一起退役。

## 托管意味着什么

用户授权的是**一个地址**，不是一次操作。谁持有那把私钥，谁就能在任何时刻让设备执行任何
shell 命令：没有范围、没有有效期、没有二次确认。这就是 `trust` 本来的语义——eXe 不为
托管方加特例，也不为它减检查。

三件必须说清楚的事：

1. **结果只有托管方能读。** 结果封给调用方的 X25519 公钥（由同一把密钥派生），所以由
   Cybion 地址签发的调用，输出只有 Cybion 能解开。用户要看结果就看 Cybion；想在自己的
   浏览器里读，必须用自己那把密钥签发。这不是限制，是"封给谁"的直接后果。
2. **撤销永远在设备上。** 从 `trust` 删掉地址并重启，之后任何签名都不再被接受。已经发出
   的密文不会变成明文，但也不会再产生新的执行。
3. **一把钥匙的暴露面是整台设备。** 所以建议**每台设备一个地址**（用户 × 设备 一对一），
   而不是一个用户一个地址：泄露一台的钥匙不波及其余，撤销也只影响那一台。
   代价是每加一台设备要填一个地址——加设备本来就要填地址。

## 为什么不走「委托证书」

早先的草案是：浏览器为每个 Thread 生成一次性会话密钥，再签一张限定 Thread、工具与有效期
的委托证书，设备额外校验证书。它需要给协议加一层作用域与过期语义——设备要理解"谁的、
什么范围、到什么时候"——而那正是 SOUL 拒绝的本地策略层。

托管把这个问题交回给信任边界本身回答：**你信任这个地址，就等于信任它背后的人和它签出的
一切。** 想缩小暴露面，就多分几个地址、少信任几个地址，而不是让设备学会读证书。
